# 立项查重工作台

用户输入项目编号，综合客户、项目名称、地点和项目内容查找其他重复候选，并查看逐项比对依据。当前交付为可运行的交互演示，全部数据虚构，未连接致远，也不执行 OA 流程操作。

## 运行与验证

```sh
npm run dev
npm test
```

访问 http://127.0.0.1:4186。页面提供重复、疑似重复、无重复和资料缺失四个示例场景，支持展开比较、查看演示规则、下载文本报告和重查本次访问记录。

## 已确认的业务范围

- 立项阶段检查重复项目，输出结论及原因。
- 综合客户、项目名称、地点和项目内容。
- 输入项目编号；不发起流程，不代审批人执行同意或退回。

## 演示判定

`dist/engine.js` 使用 Unicode 规范化及字符二元组 Dice 相似度，不提供语义判断。客户、名称、地点、内容权重为 25%、25%、20%、30%。四项完整且文本均一致时演示判定不通过；加权相似度不低于 62% 且至少三项不低于 50% 时交人工复核。缺少资料也进入复核。其余情况仅表示当前完整示例台账中未发现重复。

以上权重、阈值、通过规则均是可审查的演示假设，尚未经业务确认。相似度不是重复概率。字符匹配不能可靠处理客户别名、地址层级、不同表达、期次或标段。必须用已标注的重复与非重复真实案例校准后，才能用于正式审核。

`dist/fixtures.js` 中前三个示例使用 5 条完整示例记录；第四个场景使用额外包含缺失地点记录的 6 条台账。页面显示实际比对数量，不声称查询完整 OA。

## 真实系统接入所缺的信息

用户提供的接口文档明确了 MySQL 表 `formmain_8861`，项目编号字段 `field0007` 和主键 `ID`。它没有给出客户、项目名称、地点、项目内容、状态等字段的对应关系，也没有证明该表覆盖所有立项记录。源文档中的凭据没有复制到本项目。

上线仍需：

1. 确认立项台账覆盖范围，以及客户、名称、地点、内容、状态、期次和标段的字段映射。
2. 确认历史项目、已关闭项目、撤销项目是否参与查重，以及缺失字段的处理方式。
3. 提供已知重复和正常项目样本，确认可以自动不通过／通过的规则，其余保留人工复核。
4. 部署可访问公司内网数据库的后端，在服务端查询、做权限过滤和查重。不要将完整台账或数据库凭据发送到浏览器。为页面接入企业登录，并保留查询人、项目、候选、规则版本、数据范围及时间。
5. 数据查询失败、结果截断或范围不完整时，不输出“通过”；后端完成全范围候选检索后再给结论。对一次检查使用同一数据快照。

建议后端契约为 `POST /api/project-reviews`，请求 `{ "projectCode": "..." }`。服务端返回项目摘要、数据范围、规则版本、缺失项、结论和候选的四维比对依据。应独立处理项目不存在、编号歧义、无权限、数据源失败；前端只渲染后端结果。当前源码没有实现或假装调用这个接口。

静态 Sites 演示无需访问内网。正式接入应另行选择能连接公司数据库的服务端部署位置。
